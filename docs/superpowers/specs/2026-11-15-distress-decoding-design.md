# Distress-signal decoding — design

Date: 2026-11-15 · Owner: Person A (core, sim, tests) · Needs Person B for Nicla + dashboard parts

## Why
Today a "rescue" is a progress counter rising at a fixed speed — it looks fake. We want every
device to do **real, resumable work** whose progress % is exact, that fits the rescue story,
and where stronger devices are visibly faster but weaker ones can still finish any job.

## What it is
Each AprilTag card = a trapped person whose **distress message is locked with a PIN**.
The swarm brute-forces the PIN; when found, the message is unlocked and shown on the dashboard.

- Real work: each guess runs a deliberately slow hash (PBKDF2-HMAC-SHA256, `rounds` shared by
  all devices — the same trick real systems use for passwords). No per-device throttling.
- Difficulty = PIN length: 2 digits (100 guesses) … 5 digits (100 000).
- Durations are set by choosing each preset card's PIN: time ≈ PIN value ÷ device guesses/s.
  Target: 2–20 s on a device suited to it.

Measured: laptop ≈ 5 500 guesses/s at 500 rounds. Estimated (to measure at deploy): UNO Q ≈ 900,
Pi ≈ 180, Nicla ≈ 20–40.

## Goals / non-goals / anti-goals
- Goal: real work on all 4 devices incl. Nicla; exact progress; any device resumes any job from
  the exact guess; live "trying PIN" + decoded message on the dashboard.
- Non-goals (later): judges' custom messages, QR beacons, the beacon web page.
- Anti-goals: fixed routing (jobs pinned to devices); artificial sleeps; breaking counter mode.

## Approaches considered
1. Chess puzzles — real but laptop solves mate-in-3 in 0.3 s → would need artificial slowdown;
   different story; 3–4 h. Rejected.
2. Matrix decomposition — meaningless to judges. Rejected.
3. **PIN decoding with a slow hash (chosen)** — real work at natural speed, exact %, trivially
   resumable, fits rescue story, ~2 h for A.

## How it works
### Shared file `beacons.json` (repo root, both persons)
```json
{"rounds": 500,
 "beacons": {"7": {"title": "Maria", "digits": 4, "salt": "<hex>", "check": "<hex 16>", "ct": "<hex>"}}}
```
- `key = PBKDF2-HMAC-SHA256(pin_ascii, salt_bytes, rounds, dklen=32)`, pin zero-padded to `digits`.
- `check = sha256(key)[:8]` (hex) — a guess is right iff it reproduces `check`.
- `ct = utf8(message) XOR keystream`, keystream = `sha256(key + bytes([i]))` blocks, i = 0,1,2…
- Generated by `sim/make_beacons.py` from a list of (card, title, message, digits, pin).

### Work loop (decode mode)
- Guess order is `0 … 10^digits − 1`, ascending, on every device.
- `progress = guesses_done / 10^digits` (exact). A taker resumes at `round(progress · total)`.
- Found → `pin` = the PIN string, `progress = 1.0`, `done = true`.
- Cards without a beacon entry fall back to counter work.

### Choosing jobs — no routing
Unchanged rule: a free node takes the most urgent available job (lowest sev), whatever its
difficulty. Changes in decode mode only:
- `bid` = **seconds per guess** = 1 / my_rate (lower = better), so any node can compute anyone's
  remaining time as `remaining_guesses × bid`.
- **Take-back:** a free node may take a claimed job at ANY progress if `my_bid < 0.5 × job.bid`
  (same epoch, merge picks the lower bid as today). Replaces the `progress < 0.5` limit in
  decode mode only.
- `my_rate` is measured at node start-up (short benchmark), overridable by config `"rate"`.

### Protocol changes (SPEC.md — both must agree)
| Change | Detail |
|---|---|
| Job field `pin` | `null` until found; merge: non-null wins (if both non-null: lower string) |
| Telemetry fields | `trying` (latest guess, zero-padded string or null), `rate` (guesses/s) |
| Config | `"work": "decode" \| "counter"` (default counter), optional per-node `"rate"` |
| Bid meaning | decode mode: seconds per guess; counter mode unchanged |
| Take-back rule | as above, decode mode only |
Gossip packet size: `pin` adds ≤ 20 bytes/job → stays at 6 jobs/packet.
